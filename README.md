# mac-vpn-guard

Защита ChatGPT и Claude на macOS: приложения не выходят в интернет мимо VPN, а российские сайты при включённом VPN идут напрямую.

Проверено 23 октября 2026 на MacBook M4 с Red Shield VPN 4.1.40: при ручном отключении VPN, смене сети и сне ни один пакет за границу не ушёл мимо тоннеля (запись всех пакетов на физических интерфейсах).

## Как устроено

| Слой | Кто делает | Что даёт |
| --- | --- | --- |
| Блокировка без VPN | Red Shield: Kill Switch + «Интернет только через VPN» | Без VPN за границу не уходит ни один пакет, у всех приложений. Основная защита |
| Раздельное туннелирование | Red Shield: список российских сетей | Российские сайты с VPN идут напрямую |
| Сторож (`chatgpt-vpn-guard.sh`) | Служба launchd | Без VPN или без правил Red Shield закрывает ChatGPT, Claude, Claude Code и блокирует их адреса в `/etc/hosts`. Чинит DNS для сервисов, которые DNS VPN не находит |

Сторож — запасной слой. С VPN он спит и ждёт событий маршрутов (`route -n monitor`), без VPN проверяет приложения каждые 0,3 с. Раз в 10 с проверяет, что pf включён, набор правил Red Shield подключён, Kill Switch блокирует трафик и режим «Интернет только через VPN» активен.

## Требования

- macOS, права администратора (`sudo`).
- VPN-клиент с тоннелем `utun`, блокировкой при ручном отключении и раздельным туннелированием. Скрипты тестов и проверки правил написаны под разделы pf Red Shield (`com.redshieldvpn/ks`, `lockdown`, `ipv6_guard`); для другого клиента их нужно поправить.
- Перед установкой проверь адреса в `PROBES` (`dig +short chatgpt.com claude.ai`): они должны идти через тоннель (`route -n get <ip>`). Иначе сторож решит, что VPN выключен, и будет закрывать приложения.

## Установка и удаление

```bash
sudo ./install.sh      # сторож как служба с автозапуском
sudo ./uninstall.sh    # полный откат всего, что ставит сторож; работает без интернета
```

| Что | Где |
| --- | --- |
| Сторож | `/usr/local/bin/chatgpt-vpn-guard` |
| Служба | `/Library/LaunchDaemons/local.chatgpt-vpn-guard.plist` |
| Журнал | `/var/log/chatgpt-vpn-guard.log` |
| Домены в обход DNS VPN | `/usr/local/etc/vpn-direct-domains.txt` |

### Сервис не работает с VPN

Если DNS VPN не находит адрес (`SERVFAIL`), а Яндекс-DNS находит и сервер идёт напрямую (`en0`), добавь домен в список — сторож создаст `/etc/resolver/<домен>` (с поддоменами) и строку в `/etc/hosts`:

```bash
echo example.ru | sudo tee -a /usr/local/etc/vpn-direct-domains.txt
```

Если сервер идёт через тоннель и сервис не пускает зарубежный IP — список не поможет, нужно исключение в самом VPN-клиенте.

## Проверки

Порядок: сначала снимок и проверка отката, потом блокировка.

```bash
sudo ./pf-snapshot.sh /var/tmp/vpn-strict/backup-original   # снимок pf, только чтение
sudo ./ks-test.sh rollback && sudo ./ks-test.sh verify       # откат правил блокировки + сравнение со снимком
sudo ./ks-test.sh arm 30                                     # автооткат через 30 с
sudo ./leak-test.sh          # 4 мин: отключение VPN и смена сети, запись пакетов
sudo ./leak-test.sh sleep    # 3 мин: сон и пробуждение
sudo ./boot-capture.sh arm   # запись первых 5 минут после следующей загрузки
```

`leak-test.sh` запускай в Terminal.app: сторож закрывает Claude при отключении VPN, а с ним и встроенный терминал.

## Известные ограничения

- **DNS при загрузке.** До подключения VPN macOS шлёт DNS-запросы на внутренний DNS Red Shield (`10.254.254.254`), и правило Kill Switch пропускает их через Wi-Fi: 269 запросов за 31 с в тесте. Соединений за границу нет. Исправлять на стороне Red Shield — привязать правило к тоннелю.
- **Без VPN не работают и российские сайты** — цена режима «Интернет только через VPN».
- **Сетью не закрываются** часовой пояс, язык системы, геолокация в браузере, страна аккаунта и оплаты.
- **Своё правило pf в `com.apple/*` не работает**, если VPN-клиент заменил основной набор правил: ядро его не проверяет.
